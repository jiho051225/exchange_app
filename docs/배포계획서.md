## 1. 구조와 배포 역할

이 앱은 Next.js 15와 React 19로 만든 화면 중심 여행 기록 앱입니다 (`package.json`, `app/page.tsx`, `components/Triplog.tsx`). 서버가 영상이나 사진을 분석하는 코드는 없습니다. 사진은 사용자가 고르고 브라우저에서 Supabase Storage로 직접 올립니다 (`lib/data.ts`). 한 장 최대 10MB, 최대 5장입니다 (`components/Triplog.tsx`, `supabase/schema.sql`). 분석 1회 측정 대상은 현재 없습니다.

| 역할 | 해당 여부 | 쉬운 설명 및 근거 |
|---|---|---|
| A 정적 화면 | 해당 | 화면은 Next.js로 빌드해 CDN(사용자 가까운 곳에서 파일을 전달하는 망)으로 제공 가능. `app/`, `components/`, `package.json` |
| B 웹앱/API | 해당(웹앱), API 서버는 없음 | 브라우저 코드가 Supabase 데이터 API와 Google Maps/Places API에 직접 연결합니다. `lib/data.ts`, `components/MapView.tsx`. 로그인 처리도 익명 인증이며 자체 로그인 서버는 없습니다. |
| C 상시 연결 | 해당 없음 | WebSocket(실시간 양방향 연결)이나 실시간 구독 사용이 없습니다. `components/Triplog.tsx`에서 20초마다 데이터를 다시 읽는 방식입니다. |
| D 예약 작업 | 해당 없음 | 주기 작업·예약 실행 코드가 없습니다. |
| E 데이터 데모 화면 | 해당 | 서비스 키가 없을 때 예시 장소와 여행 기록을 브라우저 저장소에 보여줍니다. 실제 공용 서비스가 아니라 화면 체험용입니다. `README.md`, `lib/data.ts` |
| F 비동기 분석 작업 | 해당 없음 | OpenCV·FFmpeg·YOLO·PyTorch 등 분석 라이브러리와 GPU 사용이 없고, API/Worker/대기열/작업 상태 저장 구조도 없습니다. |

현재 데이터 흐름:

```text
방문자 브라우저 ── 화면 파일 ──> Vercel
       ├── 기록·댓글·익명 인증 ──> Supabase DB
       ├── 사진 파일 직접 업로드 ──> Supabase Storage (공개 사진 URL)
       └── 지도·장소 검색 ──> Google Maps Platform (브라우저 키)
```

분석 기능을 나중에 추가한다면 권장 흐름은 다음과 같습니다. 큰 영상·파일은 API 요청 본문으로 보내지 말고, API가 발급한 업로드 주소를 이용해 객체 저장소(파일 저장 공간)에 직접 올립니다.

```text
화면  API 접수  객체 저장소/작업 대기열  CPU 또는 GPU Worker  DB 결과
```

CPU Worker를 GPU로 바꿀 수 있는 구조인지 판단할 분석 작업이나 코드가 아직 없습니다. 기능을 만들 때 분석을 HTTP 요청 안에서 오래 실행하지 말고, 작업 대기열과 상태 저장을 별도로 설계해야 합니다.

## 3. 분석 1회 자원 대시보드

**대표 작업:** 없음. 프로젝트에 영상·대용량 자료 분석 기능, 분석 실행 명령 또는 분석 입력 샘플이 없습니다. 핵심 작업을 지어내 실행하지 않았습니다.

**측정 환경·명령·입력 크기·측정 날짜:** 측정하지 않음. 유효한 분석 명령이 없으므로 준비 실행을 포함한 3회 측정 모두 미실시(2026-11-21). `package.json`에 정의된 명령은 `npm run dev`, `npm run build`, `npm start`, `npm run typecheck`뿐입니다. `npm run build`는 앱 빌드이지 분석 측정 명령이 아닙니다. 따라서 부하·비용 계산에 쓸 측정값이 없습니다. 분석 기능을 구현한 뒤 실제 대표 입력 파일, 재현 가능한 단일 명령, 결과 파일 위치를 정하고 준비 실행 1회 후 동일 입력으로 3회 측정해야 합니다.

| 자원 | 실제 측정 | 배포 판단 | 상태 |
|---|---|---|---|
| 실행시간 | 해당 작업 없음 | 분석 서버 사양·대기시간 산정 불가 | 미측정 |
| 최대 메모리 | 해당 작업 없음 | 메모리 산정 불가 | 미측정 |
| CPU/GPU | 해당 작업 없음 | CPU와 GPU 사용량 모두 산정 불가 | 미측정 |
| 저장공간(입력/임시/출력) | 분석 입출력 파일 없음. 앱 사진은 1장 최대 10MB, 최대 5장. | 사진 저장은 Supabase Storage; 분석 임시공간은 해당 없음 | 미측정(분석) |
| 외부 API와 1회 비용 | 분석 외부 API 없음. Google Maps/Places는 화면 기능 사용량에 따라 청구될 수 있으나 호출 수가 정해져 있지 않음. | Google 호출량을 콘솔에서 관찰하고 일일·월별 할당량 설정 | 미측정(1회 작업 비용) |

동시 실행과 월 호출에 대한 분석 자원은 입력별 소요시간·메모리·CPU가 없어서 숫자를 만들 수 없습니다. 다음은 필요한 측정 자료와 계산식입니다.

| 동시 사용자 | CPU/GPU·메모리 | 예상 대기시간 |
|---|---|---|
| 1명 | 미측정. 1회 실행 메모리와 CPU 사용량 측정 필요 | 미측정. 1회 실행시간 측정 필요 |
| 5명 | 미측정. 병렬 실행 검증 전에는 `1명 측정치 × 5` 선형 추정만 가능 | 미측정. 대기열이 직렬이면 대략 `1명 실행시간 × 5` 추정 |
| 10명 | 미측정. 병렬 실행 검증 전에는 `1명 측정치 × 10` 선형 추정만 가능 | 미측정. 대기열이 직렬이면 대략 `1명 실행시간 × 10` 추정 |

| 월 분석 횟수 | 분석 서버 | API | DB/객체 저장소 | 합계·무료 한도 지점 |

| 10,000회 | 미측정, 분석 기능 없음 | 분석 API 없음 | 결과 저장 구조 없음 | 비용 미측정. 횟수만으로 비용 계산 불가 |

비용 산식은 기능 구현 후 `월 횟수 × 측정된 1회 CPU/메모리/저장 사용량 × 해당 서비스 단가 + 외부 API 요청 단가`로 채웁니다. 현재는 이 산식의 사용량 계수가 모두 없으며, 병렬 처리도 검증하지 않았습니다. Supabase DB·사진의 기본 서비스 한도는 분석 횟수와 직접 대응하지 않으므로 사용량을 별도 계측해야 합니다.

초보자용 결론:

1. 최소 사양: 지금은 분석 Worker가 필요 없습니다. 관리형 화면·DB·사진 저장으로 시작합니다.
2. 쾌적 사양: 분석 기능을 만든 뒤 대표 파일로 3회 측정하고, 1/5/10건 동시 실행은 별도로 검증합니다.
3. 병목: 지금 확인되는 운영 위험은 계산 자원이 아니라 공개 콘텐츠 관리 부재, 익명 사용자 남용 방지, Google 키 비용 통제, 브라우저 저장 데이터의 소실 가능성입니다.

**지금 시작할 최소 비용 CPU안:** 분석 기능 없음으로 Worker 비용 $0. 개인 시범 앱은 Vercel Hobby + Supabase Free로 시작합니다. Google 지도는 필요한 경우 결제 계정·사용량 제한을 걸고 사용합니다.

**GPU로 옮길 조건/옮길 부분:** 분석 기능을 추가한 뒤 CPU 처리 시간이 사용자 대기 목표를 반복적으로 넘거나, 실제 측정에서 GPU 가속이 유의미할 때만 Worker 코드를 별도 작업 서비스로 옮깁니다. 현재 옮길 코드나 GPU 비용을 산정할 근거는 없습니다.

## 6. 환경변수

실제 키 값은 문서화하지 않았습니다. 변수 이름만 기록합니다. 현재 `.env.example`과 앱 코드에서 확인했습니다.

| 이름 | 용도 | 현재 파일 | 배포 설정 위치 |
|---|---|---|---|
| `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` | 지도 및 장소 검색. 브라우저에 전달되는 공개 키이며 비밀로 취급할 수 없음 | `.env.example`, `components/MapView.tsx` | Vercel 프로젝트 → Settings → Environment Variables. Google Cloud에서 HTTP referrer(허용 웹사이트 주소) 제한과 API별 할당량 설정 |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 프로젝트 주소 | `.env.example`, `lib/data.ts` | Vercel 환경변수 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase 브라우저 공개 키. DB 접근 안전성은 RLS(행 단위 권한 규칙)에 의존 | `.env.example`, `lib/data.ts` | Vercel 환경변수. `service_role` 비밀 키는 등록하지 않음 |

`NEXT_PUBLIC_`로 시작하는 값은 화면 코드에 포함되어 방문자가 볼 수 있습니다. Google 키도 브라우저 개발자 도구에서 확인할 수 있으므로 비밀값으로 기대하면 안 됩니다. 웹 주소 제한·필요 API만 허용·사용량 알림을 설정하십시오.

## 8. 배포 순서

1. GitHub 비공개 저장소에 프로젝트를 올리고 `.env.local`이 포함되지 않는지 확인합니다 (`.gitignore`).
2. Supabase 프로젝트를 만들고 익명 로그인과 SQL 스키마를 설정합니다. 공개 키와 프로젝트 URL만 준비합니다.
3. Google Cloud에서 지도 API를 켜고 브라우저 키에 실제 서비스 주소 제한, API 제한, 사용량 상한/알림을 설정합니다.
4. Vercel에서 저장소를 연결하고 세 환경변수를 등록한 뒤 Hobby로 개인 시범 배포합니다. 앱 빌드 명령은 `npm run build`입니다.
5. 배포 주소에서 지도 검색, 익명 기록 작성/수정/삭제, 공개 글·댓글, 사진 업로드와 다른 브라우저에서의 데이터 유지 여부를 확인합니다.
6. 상업 공개 전에 Vercel Pro와 Supabase Pro 비용을 반영하고, 신고/운영자 숨김/남용 제한/사진 정리/백업 계획을 마련합니다.
7. 분석 기능은 실제로 구현할 때만 측정 가능한 명령·대표 입력·작업 대기열·결과 상태를 추가하고, CPU 측정 후 병목이 확인되면 CPU Worker 분리를 검토합니다. GPU는 CPU로 해결하기 어려운 증거가 생길 때 따로 비교합니다.

## 9. 문제 대비표

| 예상 문제 | 확인 위치 | 대처 |
|---|---|---|
| 지도나 검색이 안 열림 | 브라우저 개발자 도구 오류, Google Cloud API 활성화·키 제한·결제 상태 | Maps JavaScript API와 Places API(New) 활성화, 배포 주소 제한 확인, 환경변수 저장 후 재배포 |
| Supabase 기록을 저장할 수 없음 | 브라우저 오류, Supabase Auth/SQL Editor/Database 정책 | 익명 로그인 활성화, `schema.sql` 실행 여부, URL·공개 키, RLS 정책 확인 |
| 사용량 요금 급증 | Google Cloud Billing 보고서·할당량, Supabase Usage, Vercel Usage | API별 제한과 비용 알림 설정, 키 노출/오용을 확인하고 필요 시 키 교체 |
| Free 프로젝트가 응답하지 않음 | Supabase 대시보드 프로젝트 상태 | 비활성 일시 중지 여부 확인 후 재개, 상시 운영이 필요하면 Pro 고려 |
| 기록이 다른 기기에서 보이지 않거나 사라짐 | 앱의 연결 모드, 브라우저 저장 공간 | Supabase 연결 상태 확인. 체험 모드 저장은 해당 브라우저에만 남으며 데이터 복구가 어려움 |
| 사진 삭제 후에도 저장량이 줄지 않음 | Supabase Storage 버킷의 객체 목록·사용량 | 기록 삭제만으로 사진 객체가 삭제되지 않을 수 있음. 고아 파일 정리 기능 추가 |
| 공개 글·댓글 스팸 | Supabase 테이블과 사용자 신고 접수 | 현재 운영자 조치 기능이 없으므로 공개 전에 신고·숨김·작성 제한 구현 |

## 10. 배포 후 체크리스트

- [ ] 서비스 주소와 HTTPS(암호화된 웹 연결)가 열리는지 확인
- [ ] 핵심 기능: 지도/장소 검색, 여행·장소 기록, 임시저장/공개/수정/삭제, 댓글 확인
- [ ] 모바일 화면에서 입력·사진·지도 조작 확인
- [ ] 다른 브라우저와 기기에서도 데이터가 유지되는지 확인(체험 모드는 제외)
- [ ] 익명 사용자별 기록 권한과 비공개 임시저장 권한 확인
- [ ] 직접 업로드한 사진의 크기 제한·공개 여부·삭제 후 정리 확인
- [ ] Worker와 작업 대기열은 현재 없음을 확인(분석 기능 배포 시 별도 검증)
- [ ] Vercel·Supabase·Google Cloud의 사용량 및 비용 알림 확인
- [ ] 상업 공개 전 Vercel Hobby 조건을 벗어나 Pro 등 적절한 플랜 선택
- [ ] 공개 사용자 콘텐츠 신고·관리자 숨김 절차가 마련됐는지 확인
